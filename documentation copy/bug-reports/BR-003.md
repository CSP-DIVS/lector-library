# BR-003: Search With Extremely Long Query Causes 500 Error

Severity: Major
Priority: Medium
Component: Catalog/Search API
Environment: Local, CI Integration, MySQL 8.0.x
Affected Version: 1.0.0
Status: Open

## Summary
Submitting a search query longer than ~1024 characters results in an unhandled 500 error. The API should validate input length and return 400 with a clear message.

## Steps to Reproduce
1. Send GET /api/Books?search=<string of 2000 "A" characters>.
2. Observe a 500 response from the API with a generic error.

## Expected Result
- API returns 400 Bad Request with message like "Search term too long (max 256 characters).".

## Actual Result
- 500 Internal Server Error.

## Impact
- Denial of service vector and poor UX. Logs fill with exceptions.

## Evidence / Screenshots
![500 on long search](./screenshots/BR-003.png)

## Logs / Technical Notes
- Likely SQL LIKE parameter expansion or command length limit not handled.
- Add explicit validation in controller/service and cap pageSize.

## Suggested Fix
- Validate query length at controller level; return 400 with clear error.
- Consider truncating or rejecting oversize queries; add rate limiting.
