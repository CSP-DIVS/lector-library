# BR-001: Duplicate Book Created on Rapid Double-Submit

Severity: Critical
Priority: High
Component: Book Management (API + UI)
Environment: Local, CI E2E, Chrome 128, API .NET 8
Affected Version: 1.0.0
Status: Open

## Summary
When a librarian creates a new book and quickly double-clicks the Save/Submit button, two book records are created with the same ISBN. This indicates missing idempotency/duplicate request protection and/or a race in the uniqueness guard.

## Steps to Reproduce
1. Log in as a Librarian.
2. Navigate to Management -> Books -> Add Book.
3. Fill in all valid fields with a unique ISBN (e.g., 9780000000001).
4. Click the Save button twice in rapid succession (or press Enter twice quickly).
5. Observe the book list or query the API: two entries are present with the same ISBN.

## Expected Result
- Exactly one book should be created per form submission.
- The backend should enforce strong uniqueness invariants and handle duplicate submissions idempotently.

## Actual Result
- Two separate book records are created with identical ISBNs.

## Impact
- Data integrity is violated, leading to inventory inconsistencies and search confusion.
- Downstream lending and reporting may break assumptions about ISBN uniqueness.

## Logs / Technical Notes
- Integration tests show `CreateBook_DuplicateIsbn_ReturnsBadRequest` passes for sequential calls but a race exists during near-simultaneous posts.
- Consider DB-level unique index on ISBN and surfacing proper 409 Conflict on duplicate key.
- Add UI guard to disable the submit button after first click.

## Suggested Fix
- Add a unique index on ISBN at the database level (if not already present) and handle duplicate key exceptions with HTTP 409.
- Implement server-side idempotency using a request token or checksum.
- Disable UI submit while the request is in-flight.
