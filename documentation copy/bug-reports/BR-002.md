# BR-002: Book Update Appears Successful But Changes Not Persisted When Trailing Spaces Present

Severity: Major
Priority: High
Component: Book Management API
Environment: Local, CI Integration, MySQL 8.0.x
Affected Version: 1.0.0
Status: Open

## Summary
Updating a book's Author or Title with trailing spaces returns 200 OK and shows the updated value in the immediate GET, but after a subsequent full page refresh or separate API call, the old (trimmed) value reappears. This indicates inconsistent trimming/normalization between update and retrieval logic.

## Steps to Reproduce
1. Create a book with Title "Domain-Driven Design" and Author "Evans".
2. Send PUT /api/Books/{id} with Author "Evans  " (two trailing spaces).
3. Immediately GET /api/Books/{id} -> Author returned as "Evans  ".
4. Refresh the SPA or query via a new HttpClient instance -> Author returns as "Evans".

## Expected Result
- The API should consistently normalize strings (trim) or consistently store what was sent.
- Persisted and retrieved values must be consistent across requests and instances.

## Actual Result
- Inconsistent author value depending on code path/cache/ORM mapping.

## Impact
- UI shows inconsistent data; tests flake.
- Search/indexing may produce duplicate tokens.

## Logs / Technical Notes
- Likely caused by TRIM() in SELECT queries but not in UPDATE path.
- Ensure uniform normalization policy at DTO/service boundary; add DB constraint or before-save sanitization.

## Suggested Fix
- Centralize input normalization in the service layer.
- Add unit/integration tests around trimming behavior.
